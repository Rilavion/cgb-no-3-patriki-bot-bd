# Краткое ТЗ владельцу PostgreSQL и хоста Discord-бота

Проект ЦГБ №3 полностью переходит с Supabase на обычный PostgreSQL. Браузер сайта к базе напрямую не подключается: сайт работает через отдельный API на VPS, а Discord-бот подключается к PostgreSQL своим ограниченным пользователем.

## Что необходимо предоставить владельцу сайта

1. PostgreSQL версии 15 или новее.
2. Адрес сервера БД, порт и название базы.
3. SSL-режим подключения (`require`) и, если требуется провайдером, корневой сертификат CA.
4. Временную строку подключения владельца БД для применения схемы и переноса данных.
5. Отдельные строки подключения:
   - `cgb_api` — API сайта;
   - `cgb_bot` — Discord-бот;
   - `cgb_telegram` — Telegram-уведомления.
6. Разрешить подключения к PostgreSQL с IP сайта `62.109.27.123` и с IP сервера Discord/Telegram-ботов.
7. Подтвердить наличие ежедневных резервных копий и срок их хранения не менее 7 дней.

Все пароли и строки подключения передавать только в личном защищённом канале. В GitHub, Discord-канал или документацию их не публиковать.

## Что необходимо сделать с PostgreSQL

1. Создать пустую базу в кодировке UTF-8.
2. Применить по порядку:
   - `postgres-migration/01-schema.sql`;
   - `postgres-migration/02-runtime-grants.sql`.
3. Создать отдельных пользователей `cgb_api`, `cgb_bot`, `cgb_telegram` и включить их соответственно в роли `cgb_api_role`, `cgb_bot_role`, `cgb_telegram_role`.
4. Передать владельцу сайта строки подключения этих пользователей.
5. Не открывать PostgreSQL всему интернету: использовать список разрешённых IP и TLS.

Пример формата строки подключения:

```dotenv
DATABASE_URL=postgresql://cgb_bot:СЕКРЕТНЫЙ_ПАРОЛЬ@DB_HOST:5432/cgb
PGSSL=require
```

## Запуск Discord-бота

Требования: Linux-сервер, Node.js 20 LTS, доступ к Discord и к PostgreSQL.

```bash
cd /opt/cgb-discord-bot
npm ci --omit=dev
cp .env.example .env
chmod 600 .env
npm start
```

В закрытом `.env` бота необходимо указать:

```dotenv
DISCORD_TOKEN=выдаёт_владелец_Discord_бота
GUILD_ID=ID_Discord_сервера
CHANNEL_INCOMING_ID=ID_канала_заявлений
CHANNEL_RESULTS_ID=ID_канала_результатов
DATABASE_URL=postgresql://cgb_bot:ПАРОЛЬ@DB_HOST:5432/cgb
PGSSL=require
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE` новому боту не нужны и должны быть удалены из его рабочего `.env`.

После проверки запуск следует оформить как постоянную службу systemd с автоматическим перезапуском. Боту не выдаётся пользователь-владелец БД: он работает только через `cgb_bot`.

## Права Discord-бота на сервере

Боту нужны:

1. Просмотр разрешённых каналов.
2. Чтение истории сообщений и их содержимого.
3. Отправка сообщений и встроенных карточек.
4. Добавление и изменение собственных реакций.
5. Упоминание настроенных ролей.
6. Просмотр участников сервера и их ролей.

Права администратора, управления каналами, участниками и ролями не требуются.

## Важные замечания

- Папки `node_modules` не передаются и не загружаются в GitHub: зависимости устанавливаются командой `npm ci` из `package-lock.json`.
- Рабочие `.env`, токены, пароли, строки подключения, каталог `export/` и резервные копии запрещено загружать в GitHub.
- Старый `SUPABASE_SERVICE_ROLE` применяется только владельцем сайта при одноразовой выгрузке старых данных. Владельцу нового хоста и Discord-боту он не нужен.
- API сайта и Discord-бот должны использовать разные логины PostgreSQL.
- Нельзя одновременно запускать старую и новую версии бота: это создаст дубли уведомлений.
- Полное отключение Supabase выполняется только после успешной проверки сайта, файлов, авторизации и уведомлений на новой базе.

## Проверка готовности

- бот запускается без ошибок подключения;
- в таблице `bot_status` обновляется состояние бота;
- тестовая заявка с сайта создаётся и вызывает одно уведомление в Discord;
- роли и участники синхронизируются;
- после перезапуска сервера бот запускается автоматически;
- резервная копия PostgreSQL создаётся и может быть восстановлена.

Подробный порядок переноса находится в файле `Передача ЦГБ №3 на автономный PostgreSQL(Общая инструкция).md`.
