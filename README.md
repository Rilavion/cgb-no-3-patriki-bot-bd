# ЦГБ №3 — сайт и система уведомлений

Веб-портал Центральной городской больницы №3 для игрового проекта RMRP. Проект объединяет публичный сайт, личный кабинет сотрудников, внутренние заявки, тестирование, документы, состав организации и отправку уведомлений в Discord и Telegram.

Публичный адрес: [https://cgb3patriki.ru](https://cgb3patriki.ru)

Discord-бот: [github.com/Rilavion/cgb-no-3-patriki-bot](https://github.com/Rilavion/cgb-no-3-patriki-bot)

## Состояние репозитория

Файлы сайта в этом репозитории получены непосредственно с рабочего VPS из `/var/www/html` 19 августа 2026 года. Это снимок фактически опубликованной версии, включая изображения и серверные резервные копии отдельных страниц.

На момент создания снимка рабочий сайт всё ещё использует Supabase. Для проекта подготовлен переход на автономный PostgreSQL, собственный API и хранение загружаемых изображений на VPS. До финального переключения нельзя удалять старую интеграцию Supabase из действующей версии.

## Состав проекта

| Компонент | Назначение | Технологии | Подключение к данным |
|---|---|---|---|
| Сайт | Публичные страницы и интерфейс сотрудников | HTML, CSS, JavaScript | Сейчас Supabase; после переноса — собственный HTTPS API |
| API сайта | Авторизация, роли, запросы и загрузка файлов | Node.js 20, Express | Пользователь PostgreSQL `cgb_api` |
| Discord-бот | Заявки, вердикты, отчёты, роли и уведомления | Node.js 20, discord.js | Пользователь PostgreSQL `cgb_bot` |
| Telegram-бот | Уведомления по тематическим веткам группы | Python 3.11+ | Пользователь PostgreSQL `cgb_telegram` |
| База данных | Пользователи, роли, заявки, тесты и настройки | PostgreSQL 15+ | TLS и отдельные сервисные пользователи |
| Файлы | Фото состава, автопарка и другие загрузки | Каталог на VPS | Публикация через `/media/` после переноса |

## Как компоненты связаны

Целевая схема после отказа от Supabase:

```text
Пользователь
    │ HTTPS
    ▼
Nginx ───────────────► статические файлы сайта
    │ /api/v1
    ▼
API сайта ───────────► PostgreSQL
    │                     │
    │                     ├──► Discord-бот ──► Discord
    │                     └──► Telegram-бот ─► Telegram
    │
    └── /media/ ─────► файлы на VPS
```

Discord-бот и Telegram-бот не передают данные друг другу. Они независимо получают предназначенные им события из одной PostgreSQL. Браузер пользователя никогда не подключается к PostgreSQL напрямую и не должен получать пароль базы.

## Доступ и роли

Публичные страницы доступны без входа. Внутренние разделы проверяют авторизацию, роль и отдельные разрешения пользователя. Удалённый или отключённый пользователь не должен иметь возможность продолжить работу после проверки сессии.

Администратор сайта управляет пользователями, ролями, разрешениями и настройками через интерфейс. Администратор сайта не является владельцем PostgreSQL и не получает административный пароль базы.

Для PostgreSQL применяются разные учётные записи:

- `cgb_api` — серверная часть сайта;
- `cgb_bot` — только Discord-бот;
- `cgb_telegram` — только Telegram-уведомления;
- владелец базы — только для администратора PostgreSQL, создания схемы и обслуживания.

Такое разделение ограничивает последствия утечки одного пароля. Например, Discord-боту не требуется доступ к паролям пользователей сайта.

## Структура репозитория

- `*.html` — страницы сайта;
- `style.css` — общие стили;
- `main.js` и `*-engine.js` — интерфейс и логика разделов;
- `auth.js`, `roles-engine.js` — текущая авторизация и права;
- `assets/`, `images/`, `uploads/` — изображения и статические материалы;
- `docs-editor.*`, `docs-templates.js` — редактор документов;
- `supabase*.js`, `config.js` — текущая интеграция рабочего снимка с Supabase;
- `*.bak-*` — серверные резервные копии отдельных файлов, сохранённые в снимке VPS.

Файлы `*.bak-*` не должны использоваться веб-сервером как рабочие страницы. После появления стабильной истории Git их можно вынести из публичного каталога.

## Локальный просмотр

Для корректной работы страниц рекомендуется запускать локальный HTTP-сервер, а не открывать HTML через `file://`:

```bash
python -m http.server 8080
```

После запуска открыть `http://127.0.0.1:8080/`.

Без подключения к рабочей базе разделы, требующие данных и авторизации, будут работать ограниченно. Не добавляйте секретные серверные ключи в клиентские JavaScript-файлы.

## Развёртывание сайта

Рабочий каталог Nginx: `/var/www/html`.

Перед обновлением:

1. Сделать резервную копию текущей версии.
2. Проверить изменения на тестовой копии.
3. Не перезаписывать рабочие конфигурации секретами из GitHub.
4. Загрузить изменённые файлы.
5. Проверить главную страницу, вход, роли, заявки, тесты и изображения.
6. При ошибке выполнить откат на предыдущую проверенную версию.

Изменения должны вноситься через отдельные учётные записи и фиксироваться в истории Git. Общие пароли между администраторами использовать не следует.

## Переход на PostgreSQL

Для целевой системы подготовлены:

- схема PostgreSQL и разграничение прав;
- скрипты одноразового экспорта из Supabase и импорта;
- собственный API сайта;
- версии Discord- и Telegram-ботов для PostgreSQL;
- перенос изображений из Supabase Storage на VPS;
- проверка количества импортированных записей и файлов.

Владелец PostgreSQL может выполнить создание схемы и импорт самостоятельно. Передавать кому-либо пароль владельца БД не требуется. После установки он выдаёт только ограниченные строки подключения для `cgb_api`, `cgb_bot` и `cgb_telegram`.

Финальное переключение выполняется в согласованное окно обслуживания: остановка старых обработчиков, последний экспорт, импорт, проверка, запуск API и ботов, затем приёмка. Старые и новые боты не должны работать одновременно, иначе уведомления могут дублироваться.

## Discord-бот

Исходный код находится в отдельном репозитории: [cgb-no-3-patriki-bot](https://github.com/Rilavion/cgb-no-3-patriki-bot).

Для запуска требуются Node.js 20, Discord-токен и строка подключения пользователя `cgb_bot`. Зависимости устанавливаются командой `npm ci --omit=dev`; папка `node_modules` в GitHub не хранится.

Боту нужны просмотр разрешённых каналов, чтение истории и содержимого сообщений, отправка сообщений и Embed, собственные реакции, упоминание настроенных ролей и просмотр участников. Права администратора Discord, управления каналами, участниками или ролями не требуются.

## Telegram-бот

Telegram-воркер отправляет только уведомления в зарегистрированные темы частной группы. Управление сайтом через Telegram не выполняется. Токен находится только в закрытом серверном окружении.

Для запуска требуются Python 3.11+, токен Telegram-бота и строка подключения пользователя `cgb_telegram`. Discord-бот и Telegram-бот могут работать на одном сервере, но используют разные процессы и разные доступы к PostgreSQL.

## Резервное копирование

Минимальные требования:

- ежедневная резервная копия PostgreSQL не менее чем за 7 последних дней;
- отдельная копия каталога загруженных файлов;
- проверка восстановления, а не только факта создания архива;
- резервная копия файлов сайта перед каждым развёртыванием;
- доступ к копиям минимум у двух назначенных технических ответственных.

Рекомендуемые целевые показатели: восстановление критической работы сайта в течение 30–60 минут и потеря не более одних суток данных при полном отказе базы.

## Безопасность

Никогда не загружать в GitHub:

- `.env`;
- токены Discord и Telegram;
- пароли и рабочие строки подключения PostgreSQL;
- Supabase `service_role`;
- экспорт базы, персональные данные и резервные копии;
- приватные ключи и сертификаты клиента.

Для GitHub и серверов следует включить двухфакторную аутентификацию, индивидуальные учётные записи и журналирование действий. Доступы отзываются при прекращении обязанностей сотрудника.

Если секрет когда-либо был опубликован, простого удаления из файла недостаточно: секрет необходимо заменить у провайдера.

## Проверка после обновления

- главная страница и навигация открываются;
- авторизация и выход работают;
- удалённый пользователь не может войти;
- роли скрывают и открывают правильные разделы;
- новости, состав, документы и изображения загружаются;
- заявка проходит создание, рассмотрение и архив;
- тест завершается и отображает результат;
- Discord и Telegram получают по одному тестовому уведомлению;
- в браузере и серверных журналах нет новых ошибок.

## Ответственность и связь

Для устойчивой эксплуатации назначаются как минимум два технических ответственных за код и аварийное восстановление, а также как минимум два администратора интерфейса сайта. Доступ к PostgreSQL уровня владельца остаётся у владельца базы; сайту и ботам выдаются только ограниченные сервисные пользователи.

Сообщения об ошибках должны содержать адрес страницы, время, действия перед ошибкой, снимок экрана и, если возможно, текст ошибки из консоли. Токены, пароли и персональные данные в публичную заявку не прикладываются.
