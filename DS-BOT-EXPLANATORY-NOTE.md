# Пояснительная записка: Discord-бот ЦГБ №3

## Назначение

Бот связывает Discord-сервер, сайт ЦГБ №3 и единую PostgreSQL. Он отправляет заявки и результаты в выбранные Discord-каналы, синхронизирует участников/роли, обрабатывает очереди сайта и сохраняет служебные идентификаторы сообщений. Supabase не используется.

Схема работы:

```text
Браузер → API сайта → PostgreSQL ← Discord-бот → Discord
```

Браузер никогда не получает пароль PostgreSQL. Сайт работает через собственный API, а бот подключается к той же БД напрямую под отдельным пользователем.

## Основные модули

- `index.js` — запуск, электронные заявления и подключение модулей;
- `postgres-client.js` — безопасные параметризованные запросы и события `LISTEN/NOTIFY`;
- `complaints.js` — жалобы и реестр нарушений;
- `requests.js` — заявки сотрудников и вердикты;
- `test-report.js` — результаты тестов;
- `vp.js`, `vp-request.js`, `vp-report.js` — состав Discord и проверки АБ;
- `payroll.js` — премирование;
- `supply.js` — поставки;
- `report.js` — отчёты;
- `raids.js` — рейды;
- `msg.js` — сообщения, сформированные на сайте.

## Настройка через сайт

Сайт сохраняет настройки каналов и маршрутов в PostgreSQL. Бот получает изменения через события базы и периодические проверки. Каналы и роли сначала создаются в Discord; бот синхронизирует их в таблицы `ds_channels`, `ds_roles`, `ds_guild_roles` и `ds_members`, после чего они появляются в выпадающих списках сайта.

Настройки не лежат в исходниках бота. Поэтому перенос папки без переноса PostgreSQL не переносит выбранные каналы, историю и очереди.

## Переменные запуска

| Переменная | Назначение |
|---|---|
| `DISCORD_TOKEN` | Рабочий токен приложения Discord. |
| `GUILD_ID` | ID Discord-сервера. |
| `CHANNEL_INCOMING_ID` | Канал новых электронных заявлений. |
| `CHANNEL_RESULTS_ID` | Канал результатов рассмотрения. |
| `DATABASE_URL` | Строка подключения отдельного пользователя бота к PostgreSQL. |
| `PGSSL` | `require` для TLS; `no-verify` только временно для самоподписанного сертификата. |
| `BACKFILL_ON_START` | Нужно ли при запуске дочитать пропущенные сообщения. |
| `BACKFILL_LIMIT` | Максимум сообщений для дочитывания. |
| `VP_SYNC_MINUTES` | Период полной синхронизации ролей и участников. |

## Права Discord

Боту нужны только разрешения, соответствующие используемым каналам: просмотр каналов, отправка сообщений, чтение истории, добавление реакций, прикрепление файлов и использование внешних эмодзи. Для синхронизации состава также нужны Server Members Intent и доступ к участникам. `Administrator` не требуется, если права выданы точечно.

## Перенос и запуск

1. Получить от владельца БД `DATABASE_URL` и доступ по сети с хоста бота.
2. Применить к базе схему сайта и импортировать данные по общей инструкции миграции.
3. Скопировать `.env.example` в `.env` и заполнить секреты.
4. Выполнить `npm ci --omit=dev`.
5. Запустить `npm start` или systemd-службу.
6. Проверить лог входа в Discord, статус синхронизации и новые записи в `bot_status`.

## Что загружать в GitHub

Загружаются исходники `.js`, `package.json`, `package-lock.json`, документация, `.env.example` и `.gitignore`. Не загружаются `.env`, `node_modules`, логи и рабочие токены.

## Безопасность

- Пароль PostgreSQL и `DISCORD_TOKEN` должны храниться только в защищённом окружении хоста.
- При утечке токен Discord отзывается в Developer Portal, пароль пользователя БД меняется владельцем базы.
- Бот не должен использовать владельца БД: ему выдаётся отдельный пользователь с правами на рабочие таблицы и функции.
- Строки SQL собираются только через параметризованный клиент; значения из Discord не подставляются в SQL как текст.
